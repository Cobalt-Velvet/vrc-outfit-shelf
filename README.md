# vrc-outfit-shelf

VRChat向けのアセット管理サービス。購入したアセットと、それをどのアバターにどう使ったかを記録します。

## なぜ作ったか

VRChatで活動する中で、「以前買ったアセットがどこにあるか分からない」「どのアバターに適用したのか分からない」という声を周りから何度も聞きました。困りごとは「何を持っているか」と「それをどこにどう使ったか」の二つに分かれるため、この二つを別々に記録し、後から結びつけられる構造を前提に設計しています。

## 技術構成

Go / PostgreSQL / Docker Compose（pgx, net/http, html/template, bcrypt）

## 現在の状態

開発中です。現在までに以下を実装しています。

- データベースの設計・構築とシードデータ
- 会員登録（パスワードは bcrypt でハッシュ化して保存）
- セッション方式のログイン・ログアウト
- ログインが必要なページの保護（未ログインの場合はログイン画面へ移動）
- アセットの一覧表示・登録（ログイン中の利用者のアセットのみ）
- html/template による画面描画

今後は、アバター・プリセット・対応関係のAPIと所有権チェック、画面の整備、テスト、デプロイを予定しています。

## 設計上の判断

### 認証

- 認証は JWT ではなくセッション方式を採用しました。サーバー1台・サーバーサイドレンダリングの構成では JWT の利点が生きず、ログアウトを確実に処理できるためです
- ログアウト時はセッションをデータベースから削除します。Cookie を消すだけでは、そのセッションIDが有効期限（ログインから7日）まで使えてしまうためです
- セッションIDは crypto/rand で生成し、Cookie には HttpOnly と SameSite=Lax を付けています。Secure 属性はローカル環境が HTTP のため現在は付けておらず、デプロイ時に有効にします
- ログイン確認は各ハンドラーに書かず、ミドルウェア（requireLogin）の一か所にまとめています。確認したユーザーIDはリクエストの context に入れてハンドラーへ渡します。グローバル変数に置くと、同時に届いたリクエストの間で値が混ざるためです
- ログアウトは POST で受け付けます。HTTP では GET はサーバーの状態を変えないメソッドとされており、GET にすると他のサイトのリンクを開いただけでログアウトさせられるためです
- ログイン失敗時は「ユーザーが存在しない」と「パスワードが違う」を区別せず、同じメッセージとステータスコードを返します
- 会員登録で名前が重複した場合は 409 を返します。名前がそのままログインIDになる構造のため、その名前が登録済みかどうかが分かってしまう点はトレードオフとして受け入れています

### データ設計

- アバターとアセットは一つのテーブルにまとめず、分けています。まとめると、対応関係・プリセット・改変履歴で「アバターでなければならない」という制約をデータベース側で表現できなくなるためです
- 他人のアバターに他人のアセットを結びつけられないようにする利用者の境界は、アプリケーション側で検査する方針です。データベースの複合外部キーで表すには中間テーブルにも利用者IDを持たせる必要があり、データの持ち方が冗長になるためです

### 画面

- 画面は html/template で描画し、利用者の入力を自動でエスケープすることで XSS を防いでいます

## 動かし方

```bash
# 1. .env を用意（.env.example をコピーし、パスワードを設定）
cp .env.example .env
# .env の中身: POSTGRES_PASSWORD=任意のパスワード

# 2. データベースを起動
docker compose up -d

# 3. スキーマとシードデータを投入
docker compose exec -T db psql -U seolhui -d maindb < schema.sql
docker compose exec -T db psql -U seolhui -d maindb < seed.sql

# 4. 接続情報を環境変数に設定（パスワードは .env と同じもの）
export DATABASE_URL="postgres://seolhui:<password>@localhost:5432/maindb"

# 5. サーバーを起動
go run .
```

PowerShell の場合は 3 と 4 を以下に置き換えてください。

```powershell
Get-Content schema.sql | docker compose exec -T db psql -U seolhui -d maindb
Get-Content seed.sql | docker compose exec -T db psql -U seolhui -d maindb
$env:DATABASE_URL = "postgres://seolhui:<password>@localhost:5432/maindb"
```

起動後、以下のページで確認できます。

- 会員登録: http://localhost:8080/signup
- ログイン: http://localhost:8080/signin
- アセット一覧・登録: http://localhost:8080/assets（ログインが必要です。ログアウトはこのページのボタンから行えます）

シードデータのユーザーはパスワードが設定されていないためログインできません。動作確認の際は、先に会員登録をしてからログインしてください。一覧にはログイン中の利用者が登録したアセットだけが表示されるため、会員登録した直後の一覧は空です。
